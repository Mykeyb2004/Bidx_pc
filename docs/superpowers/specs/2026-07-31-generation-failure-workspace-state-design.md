# 章节生成失败工作区状态设计

## 问题

大模型调用失败后，错误详情只写入当前正文控件。用户关闭错误弹窗后，批量生成流程刷新目录树并恢复选择，随后触发的章节预览会重新渲染工作区。预览逻辑没有失败状态，只能回退到“尚未生成正文”，导致刚展示的错误信息消失。

## 目标

- 失败信息在当前应用会话内按章节保留。
- 关闭弹窗、刷新状态、筛选目录、切换章节后返回，都能重建失败视图。
- 重试开始、生成并保存成功、切换配置或显式重载大纲时清除过期失败状态。
- 流式和非流式生成失败时都保留实际已返回正文。
- 错误诊断不计入正文字数，也不写入输出文件。

## 非目标

- 不在应用重启后恢复失败信息。
- 不修改输出文件格式或保存协议。
- 不通过扩大 Tk 树事件抑制范围解决问题。

## 状态模型

新增不可变失败快照：

```python
@dataclass(frozen=True)
class WorkspaceGenerationFailureState:
    feedback: GenerationErrorFeedback
    partial_content: str = ""
```

`MainWindow` 使用 `_workspace_generation_failures` 按 `heading.full_path` 保存当前配置和大纲下的失败快照。配置切换或显式重载大纲会清空整个映射，因此同名章节不会跨项目泄漏。

## 渲染规则

章节预览按以下顺序选择状态：

1. 当前正在生成：显示实时缓冲区。
2. 最近生成失败：显示部分正文和结构化错误诊断。
3. 已保存文件：读取并显示文件正文。
4. 默认空状态。

失败视图由快照完整重建，不依赖正文控件已有内容。部分正文与诊断文案组合显示，但 `generated_char_count` 只统计 `partial_content`。

## 生命周期

- `_report_generation_failure` 在打开模态弹窗前登记失败快照。
- `GenerationSession` 开始新尝试时清除同章节旧失败并重置实时缓冲。
- 生成成功时旧失败已经由本次尝试清除，随后预览正常读取保存文件。
- 普通状态刷新、树重绘、筛选、章节切换不清除失败快照。
- `_switch_to_config_path` 成功切换后清空失败快照。
- `reload_outline` 成功后清空失败快照并重新渲染当前选择。

## 部分正文

后台生成始终在 `content_parts` 中收集正文。流式模式下片段已逐条进入 UI 队列；非流式模式若中途异常，应在错误事件前把 `"".join(content_parts)` 放入正文队列。主线程处理错误时从章节缓冲区构建失败快照，从而保留真实正文，而不是只有 `has_partial_output` 布尔值。

## 验证范围

- 弹窗关闭和目录重选后失败信息仍可见。
- 切走章节再返回时可重建失败视图。
- 重试开始后旧失败被清除。
- 非流式部分正文在异常后仍保留。
- 失败优先于旧保存文件，诊断文案不计入字数。
- 配置切换和显式大纲重载会清除状态。
- 现有生成中预览、筛选、批量刷新和配置切换测试保持通过。
