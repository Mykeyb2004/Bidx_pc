# 项目根目录优先的新建配置向导设计

## 背景

当前新建配置向导先让用户选择招标文件，再根据招标文件位置推导项目根目录。这会让招标文件的位置意外决定配置文件、采购需求、评分标准、大纲和输出目录的位置，也不利于用户把一个投标项目的相关文件集中管理。

节点撰写计划功能已经支持 `project.inputs.writing_plan_file`，配置编辑器也已展示该字段，但新建向导仍把它留空。用户新建项目后需要再进入配置编辑器补充路径，且向导不会提前创建或校验计划库。

本设计把项目根目录改为向导的第一个确定项，并让后续默认路径统一从该目录派生。同时补齐节点撰写计划文件的选择、创建、复用和校验流程。

本设计替代 `2026-04-30-new-config-wizard-design.md` 中“先选择招标文件，再推导项目根目录”的流程。未被本设计明确修改的导入、抽取、取消清理和大纲准备行为继续沿用现有实现。

## 目标

- 新建配置时先选择一个已存在的项目根目录。
- 配置文件和业务资料默认集中在该项目根目录下。
- 后续所有默认路径都以用户确认的项目根目录为唯一派生来源。
- 新建配置默认启用 `./撰写计划.json`，并在向导完成时创建或校验该文件。
- 允许引用项目外的自定义节点撰写计划 JSON，不复制用户文件。
- 为所有文件选择弹窗提供严格的业务文件类型过滤。
- 保持配置编辑器、运行时配置解析和 `WritingPlanStore` 使用同一套路径及 JSON 语义。

## 非目标

- 不由向导创建项目根目录；用户必须先创建并选择一个现有目录。
- 不强制所有用户文件都位于项目根目录，项目外路径仍可使用。
- 不复制项目外的自定义节点撰写计划文件。
- 不增加节点计划的导入合并、格式升级或批量编辑功能。
- 不改变 JSON v1 的数据结构、节点精确匹配规则或生成时快照语义。
- 不重写招标文件转换和章节抽取算法。

## 已确认的产品决策

- 采用“向导状态统一管理写作计划路径”的方案。
- 用户选择项目外的自定义写作计划 JSON 时，直接引用原文件，不复制。
- 新建配置完成时必须存在节点撰写计划文件；缺失时立即创建空 JSON v1。
- 默认位置已有合法文件时直接复用，绝不覆盖。
- 默认位置已有非法文件时阻止完成向导。
- 项目根目录只能选择现有目录，向导不负责创建。
- 配置文件默认保存为 `项目根目录/config_<项目文件夹名>.yaml`。
- 文件弹窗严格过滤受支持类型，不提供“全部文件”选项。

## 向导流程

### 1. 项目位置

第一步只确定项目工作区：

- 用户通过目录选择器选择一个已存在的项目根目录。
- 未选择目录、目录不存在或目标不是目录时不能进入下一步。
- 界面提示每个投标项目使用独立文件夹，但不强制目录必须为空。
- 配置文件路径自动显示为 `项目根目录/config_<项目文件夹名>.yaml`。
- 项目文件夹名需要经过现有配置文件名清理规则，避免非法字符进入文件名。
- 本向导不提供把配置文件移到项目外的入口。
- 默认配置文件已经存在时不覆盖；界面提示用户打开已有配置或选择其他项目根目录。

配置文件与项目根目录位于同一目录，因此保存后的 canonical YAML 使用：

```yaml
project:
  root_dir: "."
```

### 2. 招标文件

第二步提供“选择招标文件”和“手动创建”两个入口。

- 选择招标文件只能更新来源文件、复制目标和导入目录，不能重新推导或覆盖项目根目录。
- 招标文件已在项目根目录内时直接使用。
- 招标文件位于项目根目录外时，沿用现有逻辑，在向导完成过程中复制到 `项目根目录/招标文件/<原文件名>`。
- 手动创建不要求招标文件，后续由用户选择采购需求和评分标准 Markdown 文件。

### 3. 项目资料

默认路径为：

```text
项目根目录/项目要求/项目采购需求.md
项目根目录/项目要求/评分标准.md
```

- 自动抽取继续写入上述默认位置。
- 手动模式允许选择项目内或项目外的已有 Markdown 文件。
- 项目内文件保存为相对 `project.root_dir` 的 POSIX 路径。
- 项目外文件保存为绝对路径，并在检查页标记为“项目外文件”。
- 本次改动只鼓励集中管理，不复制项目外的采购需求或评分标准文件。

### 4. 基本信息与项目输出

该步骤保留投标主体名称和大纲来源选择，并增加节点撰写计划文件。默认路径为：

```text
项目根目录/投标大纲.md
项目根目录/撰写计划.json
项目根目录/output
```

节点撰写计划字段提供：

- 可编辑路径输入框；
- 仅选择已有 `.json` 文件的按钮；
- 当前路径是“项目内文件”还是“项目外文件”的状态；
- 已有文件的格式校验状态。

默认路径允许尚不存在，因为向导完成时会创建。用户也可以手工输入另一个尚不存在的 `.json` 路径；其父目录必须已经存在且可写。通过弹窗选择自定义计划时只能选择已有 JSON 文件。

### 5. 检查并创建

检查页汇总：

- 项目根目录；
- 配置文件保存位置；
- 将复制的招标文件；
- 采购需求和评分标准文件；
- 大纲文件；
- 节点撰写计划文件及其“新建”或“复用”状态；
- 输出目录；
- 所有项目外引用。

只有全部校验通过后才能执行“保存并应用”。成功后继续复用现有配置切换和大纲准备流程。

## 默认路径与根目录联动

向导刚打开时不使用当前配置目录或程序目录预填项目根目录。第一步只维护尚未确认的目录输入；用户选择并通过校验后，才调用纯逻辑构造函数创建 `NewConfigWizardState`。这样后续步骤不会在用户确认前持有一组错误的默认路径。

`NewConfigWizardState` 增加 `writing_plan_path: Path`，项目根目录成为状态构造的必需输入。状态默认值统一为：

```text
config_path       = root / f"config_{sanitized_root_name}.yaml"
requirements_path = root / "项目要求" / "项目采购需求.md"
scoring_path      = root / "项目要求" / "评分标准.md"
outline_path      = root / "投标大纲.md"
writing_plan_path = root / "撰写计划.json"
output_dir        = root / "output"
import_dir        = root / ".bid_writer" / "imports" / "pending"
```

用户返回第一步更换项目根目录时：

- `config_path` 始终按新根目录和新目录名重新派生。
- 某个业务路径若仍等于旧根目录下的默认值，则迁移到新根目录下的对应默认值。
- 某个业务路径已被用户改成自定义值时保持不变。
- 招标文件选择状态保持不变，但需要重新计算它是否位于项目内以及复制目标。
- 界面字段和检查页必须同步刷新。

该规则沿用现有“比较旧默认值后再重定位”的模式，不需要为每个路径增加额外的 dirty 标记。

## 路径序列化

- 配置文件固定在项目根目录内，因此 `project.root_dir` 保存为 `.`。
- 项目内输入和输出路径保存为 `./...`，并统一使用 `/` 分隔符。
- 项目外输入文件保存为绝对路径，不生成 `../...` 路径。
- `project.inputs.writing_plan_file` 在默认情况下保存为 `./撰写计划.json`。
- 新建向导不得再把 `writing_plan_file` 留空。

## 严格文件类型过滤

向导和配置编辑器的文件选择器按字段传入明确的 `filetypes`，且不增加“全部文件”选项：

| 用途 | 允许扩展名 | 对话框类型 |
|---|---|---|
| 项目根目录、输出目录、缓存目录 | 不适用 | 目录选择 |
| 招标文件 | `.pdf`、`.docx`、`.doc`、`.xlsx`、`.xls` | 打开文件 |
| 配置文件 | `.yaml`、`.yml` | 打开或保存文件 |
| 大纲、采购需求、评分标准 | `.md` | 打开文件；生成大纲位置使用保存文件 |
| 节点撰写计划 | `.json` | 打开文件 |
| 角色提示词文件 | `.md` | 打开文件 |

文件弹窗过滤只是第一层约束。用户可以手工输入路径，因此步骤校验和配置保存校验还必须检查扩展名，并给出字段级错误。

## 节点撰写计划文件生命周期

### 公共存储能力

在 `writing_plan_store.py` 中增加公开的初始化能力，供向导调用。该能力负责：

- 文件存在时复用现有 JSON v1 解析和完整校验；
- 文件不存在时创建规范的空 JSON v1；
- 返回“已创建”或“已复用”结果，供向导记录和展示；
- 对损坏 JSON、未知版本、重复节点、字段类型错误、编码错误和权限错误提供可展示的异常；
- 保证已有文件绝不被覆盖。

空文件内容固定为：

```json
{
  "version": 1,
  "items": []
}
```

文件使用 UTF-8、两空格缩进、中文不转义并以换行结尾，与现有 `WritingPlanStore` 写回格式一致。

### 保存顺序与回滚

“保存并应用”按以下顺序执行：

1. 同步并校验全部向导字段和文件扩展名。
2. 构建并校验 `ConfigEditorDocument`，此时不写磁盘。
3. 校验已有写作计划文件，或以排他方式创建缺失的空文件。
4. 保存配置文件。
5. 执行现有配置切换和后续大纲准备。

如果第 4 步保存配置失败：

- 只删除第 3 步由本次向导新建的空写作计划文件；
- 不修改或删除任何向导开始前已经存在的文件；
- 回滚路径记录在现有 `created_paths` 范围内，不使用目录名推断删除目标。

默认写作计划文件的父目录就是已确认存在的项目根目录。自定义路径的父目录不存在时阻止完成，向导不隐式创建任意外部目录。

## 已有配置的编辑体验

配置编辑器继续使用现有入口：

```text
项目信息 -> 输入资源 -> 节点撰写计划文件
```

优化规则：

- “浏览”只允许选择 `.json` 文件。
- 选择项目内文件后保存为相对项目根目录的路径。
- 选择项目外文件后保存为绝对路径，不复制文件。
- 已有文件在保存配置前执行 JSON v1 校验，错误时阻止保存并显示具体原因。
- 保留字段为空的兼容语义，已有配置可以选择不启用节点撰写计划库。
- 保留手工填写尚不存在路径的旧兼容行为；配置编辑器不在保存 YAML 时创建该文件，首次保存非空节点计划时仍可由 `WritingPlanStore` 创建。

## 组件边界

### `bid_writer/new_config_flow.py`

- 维护根目录优先的纯状态模型。
- 根据现有项目目录派生全部默认路径。
- 处理根目录变化时的默认路径重定位。
- 构建包含 `writing_plan_file` 的 editor model。
- 处理项目内相对路径与项目外绝对路径序列化。

### `bid_writer/new_config_wizard.py`

- 把“项目位置”调整为第一步。
- 管理严格文件过滤、字段状态和步骤校验。
- 不自行解析或写入节点撰写计划 JSON。
- 在完成流程中协调计划库初始化、配置保存和精确回滚。

### `bid_writer/writing_plan_store.py`

- 作为 JSON v1 格式、校验和写入的唯一来源。
- 提供不覆盖已有文件的初始化接口。
- 继续负责运行时加载、保存、指纹和外部修改冲突检测。

### `bid_writer/config_editor_dialog.py`

- 为路径控件声明文件用途或文件类型。
- 使用用途对应的严格过滤规则。
- 对已有写作计划文件显示可操作的格式错误。

### `bid_writer/config_editor.py`

- 保持 canonical YAML 规范化和渲染职责。
- 新建配置默认模型仍可保留空的可选字段语义；新建向导负责明确写入 `./撰写计划.json`。
- 增加必要的扩展名和已有计划文件校验入口时，不在此处重复实现 JSON 解析。

## 错误处理

- 项目根目录为空、不存在或不是目录：停留在第一步。
- 默认配置文件已经存在：不覆盖，提示打开已有配置或改选项目根目录。
- 项目根目录不可读或配置目标不可写：完成前报错。
- 手工输入路径扩展名不匹配字段用途：在当前步骤报错。
- 写作计划文件损坏或 schema 非 v1：显示具体路径和解析原因，禁止保存配置。
- 写作计划文件在预检后被外部替换：初始化或保存阶段重新检查，不覆盖新内容。
- 写作计划文件权限不足：保留向导输入和用户已有文件，允许修复后重试。
- 配置保存失败：只回滚本次创建的空计划文件，并保留向导供用户重试。
- 严格过滤不改变底层安全边界；所有路径在使用前仍需独立校验。

## 验收标准

- 新建配置向导第一步要求选择现有项目根目录。
- 选择招标文件不再改变项目根目录。
- 配置文件默认保存到项目根目录并按项目文件夹命名。
- 所有默认业务路径从项目根目录派生。
- 新建配置必定写入非空的 `project.inputs.writing_plan_file`。
- 向导完成后默认写作计划文件存在且为合法 JSON v1。
- 已有合法计划文件原样复用，非法文件阻止完成，任何已有文件均不被覆盖。
- 项目外自定义计划文件直接引用且不复制。
- 所有文件弹窗严格过滤受支持扩展名且没有“全部文件”。
- 配置保存失败不会留下本次新建的孤立计划文件。
- 定向测试和完整测试套件通过。
