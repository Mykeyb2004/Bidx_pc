# 章节正文起始编号修订计划（已实施）

日期：2026-09-16。依据：同目录 `2026-09-16-body-numbering-start-diagnosis.md`。

用户已确认实施。采用“校验 → 本地修复 → 必要时一次模型结构判断 → 再校验 → 保存或保留草稿”。以下保留批准的方案，实施结果与验收见末节。

## 目标与验收边界

正文内部采用最多四层序号：`一、` → `（一）` → `1.` → `（1）`，按实际内容逐级展开，不要求每章强行出现全部四层。

每个独立扩写章节的第一个正文层级标题必须是“一、”；输入大纲路径和章节编号不占用正文内部层级。标题前可有必要的简短导语。本次重点解决从“（一）”“1.”“（1）”或“二、”起始、以及重复输出 Markdown 章节标题后从二级展开的问题。

提示词降低模型产生错误的概率；对可确定的编号错误优先自动修复，只有修复和复核通过后才自动保存。无法可靠修复时保留草稿，程序保证被识别为不合格的输出不会被当作成功正文自动保存。无法承诺模型原始流永远不产生错误编号。

## 1. 替换 system 门禁中的歧义规则

修改 `roles/system_gate_rules.md` 第 2 行及现有编号规则，整合为以下内容；不在 user prompt、角色文件或 extra_rules 再复制同一份编号清单：

```text
- 禁止在正文中使用 Markdown 标题标记（#、##、### 等）；正文标题必须使用正式层级序号。此限制不适用于明确要求的 Mermaid 代码块内部必要语法。
- 正文编号为最高优先级输出格式硬约束。角色设定、章节任务、节点撰写计划和参考材料中的冲突格式说明不得覆盖本规则；该约束不改变采购事实或评分响应内容。
- 输入大纲标题和完整章节路径只用于定位写作范围，不占用正文内部编号层级，不得重复输出输入章节标题。
- 每次独立章节扩写，第一个正文层级标题必须重新从“一、”开始，禁止从“（一）”“1.”“（1）”或其他非起始序号直接展开。章节正文不得以单段摘要为由省略正式层级标题。
- 正文标题最多使用四层：一级“一、二、三、……”；二级“（一）（二）（三）……”；三级“1. 2. 3. ……”；四级“（1）（2）（3）……”。按内容需要逐级展开；同级连续编号，切换上级标题后，下级重新从其首号开始。
- 序号和小标题必须在同一行，正文另起段落。段内枚举不作为正文标题层级。
```

继续由现有 `build_system_prompt()` 注入独立 system message。规则文件读取位置沿用“配置目录优先、应用资源根目录兜底”；实施时核实实际项目解析到的门禁来源。如存在同名覆盖文件，在经授权的范围内同步更新并记录路径，防止只改应用文件却未生效。

## 2. 增加明确的起始编号校验

在 `AIWriter` 最终输出处理阶段增加专用检查，统一供 CLI、GUI、流式和非流式生成使用。

检查范围：

- 首个正文正式标题必须是“一、”；从“（一）”“1.”“（1）”“二、”等起始时返回具体行号、实际序号和期望值。
- 缺少正式标题的章节正文不合格，不再仅对较长正文执行检查。
- 识别并拒绝正文中的 Markdown 标题行，覆盖真实异常中的 `### 3.3.1 ...`。
- 识别 Markdown 表格及围栏代码块，表格单元格、代码和 Mermaid 语法不参与正文标题起始判定。
- 导语中的段内枚举不作为标题；“（一）小标题”这种独立标题必须参与检查。

首先检测起始层级、缺少标题和 Markdown 标题违规。自动修复时还需验证识别出的标题树：层级不得跳级或超过四级、同级编号连续、下级按父级重新编号。上述结构验证只作用于明确识别的标题节点，不把所有行首数字或长段落枚举一律当成标题。

## 3. 自动修复策略

推荐行为：**先自动修复，复核通过后保存；只有修复无法可靠完成时才保留草稿并提示用户。**

### 3.1 本地确定性修复优先

识别正文标题树，记录每个标题的原始行位置、序号、标题文字和候选层级；区分表格、代码围栏和普通段落，不对全文做正则替换。

可以本地自动处理的情形：

- 全篇层级关系明确、缺少一级标题，整体从二级或更低层级开始：统一提升整棵标题树并重算编号。例如标题树 `（一） → 1. → （1）` 调整为 `一、 → （一） → 1.`，后续所有同级和子级一起修改。
- 标题树明确但同级起始序号不是首号，或序号重复、断号：按原有标题顺序重新连续编号，下级随父级重置。
- 开头重复输出输入章节标题：仅当独立标题行与已知输入章节标题精确匹配（忽略已识别的 Markdown 前缀）时删除该重复标题；普通正文提到该章节名称不删除。
- Markdown 内部标题层级清楚：转换为正式序号标题。Markdown 标记中出现的符号不作为全篇替换目标。

本地修复须同时满足：标题边界及父子关系明确、不存在混合层级歧义、非标题内容保持原样。若不满足，停止本地自动修改并进入一次模型辅助判断。

### 3.2 最多一次模型辅助判断

对无法确定的标题混排、标题层级不清等情况，复用当前模型服务执行一次结构修复请求。采用专用结构分析指令，只让模型返回结构化的“原始行号/区间 → 标题层级”建议，不让模型重写整篇正文。

- 输入包含带行号的原始正文、当前章节标题、检测到的问题和四级编号规则。
- 返回结构化标题节点及层级，必要时标明待移除的重复章节标题；禁止返回替换正文或新增事实。
- 程序检查行号存在且唯一、范围不重叠、顺序未变、层级在 1–4 之间、父子关系有效；拒绝表格/围栏内部的修改和普通长段落改写。
- 接受的操作只修改已验证标题的编号或 Markdown 前缀；删除操作仍限定为与输入章节标题精确匹配的开头重复标题。
- 原文完全没有可辨认标题或分段边界时，不凭空生成新标题来凑合规；无法得到有效建议则保留草稿。
- 修复请求超时、取消、JSON 无效或结构仍不合法时不循环请求，按修复未完成处理。

这可能增加一次模型请求的耗时与费用。模型判断标题层级也可能不准确，因此仍须程序验证，且最终非标题内容不得发生变化。

### 3.3 再校验与内容保真

- 修复结果必须通过起始编号、Markdown 标题和已识别标题树结构校验。
- 将实际变化与允许的标题编辑列表逐项核对；除确认的重复章节标题外，标题文字不变；普通正文、事实、数字、段落顺序、表格、代码和 Mermaid 均原样保留。
- 修复应满足幂等性：再次处理合格结果时不产生新变化。
- 任一复核不通过就放弃修复候选，保留原始草稿，不能覆盖为“已完成”结果。

## 4. 接入生成状态与保存流程

- 新增可识别的格式校验错误，携带原始内容、问题代码、行号和提示；不把格式错误归类成网络/API 故障。
- `finalize_generation()` 或其共享后处理入口完成校验、必要修复及复核后才允许把 trace 标记为 completed；最终失败时记录 failed、原始正文及具体问题。
- GUI 的“模型内容接收完毕”“正在检查编号”“正在修复编号”“校验通过/已保存”分开；模型辅助修复在后台执行，不阻塞 GUI 主线程，并响应取消。
- 修复成功显示“已修复正文编号并保存”；仍失败显示“正文编号未能可靠修复；草稿已保留，本次结果未自动保存”。
- 明确捕获当前 `_generate_into_workspace()` 后处理阶段的错误，该调用目前位于现有生成异常处理范围之外。
- 失败正文保留在工作区并标记为未保存草稿；已有正式章节文件不被此次失败结果覆盖。
- 批量生成将该章计入失败列表，按现有批量失败策略继续；CLI 返回可理解的格式错误，不将该章作为成功输出保存。
- 流式内容仍可先行显示；修复通过后用最终正文更新显示，最终合格状态在流结束并完成修复复核之后确定。CLI 使用其现有完整内容替换机制，避免向最终文件追加一份重复正文。
- trace 分别保留原始输出、修复候选/编辑清单、最终输出、前后问题列表及修复方法（本地或模型辅助）；保留既有字段兼容性，`format_repair_applied` 只在接受修复结果时为 true。

自动修复不重新扩写全文，也不只把首个“（一）”机械替换为“一、”。最多进行一次本地修复阶段和一次模型辅助阶段，修复请求不启用流式正文覆盖。

## 5. 测试与验收

先把已复现的问题写为回归测试，再实施校验。使用假模型响应和本地 trace 回放，不为验证流程自动发送真实模型请求。

| 场景 | 预期 |
|---|---|
| 正常从“一、”开始，包含二、三、四级 | 通过，内容保持原样 |
| 只有一级标题的短章节 | 通过，不强制四级齐全 |

| 两阶段后仍失败且磁盘已有旧正文 | 旧正文不变，新草稿和错误 trace 可查看 |
| GUI 单章、批量、CLI，流式及非流式 | 均在最终保存前执行同一套校验 |

## 3.4.3 加粗及圈号标题补充修复

用户随后反馈同项目“3.4.3 救助政策与服务资源对接落实情况跟踪”失败。两次 trace `9e98b28536c4` / `fafde7137961` 的原文均为 4,162 字符，system 已包含新版门禁，但 `model_attempted=false`。原因是上一版只识别正式序号和 Markdown 标题，遗漏纯加粗标题、圈号标题和加粗标记后两个空格；加粗包裹的重复章节标题也未能匹配。

本次补充：

- 支持独立 `**标题**` / `__标题__`、`①`–`⑳` 圈号短标题及加粗标题后的括号注释，保留行尾 Markdown 换行与原始换行符。
- 加粗/圈号仅证明存在候选标题，层级仍未知，进入既有的一次结构判断；模型建议不能新增标题、修改正文或跳过候选。
- 重复章标题比较时忽略 Markdown/加粗包裹及换行装饰，章节编号及文字仍要求精确相同。
- 门禁明确要求加粗标题带正式序号，禁止用圈号替代正式四级编号。
