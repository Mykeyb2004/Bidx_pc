## 结论

这次存在三类不同故障，不能统一归因为“大模型不会写”或一个参数不兼容：

1. 当前 API 基础地址缺少 `/v1`，实际请求落到返回 HTML 的网页路由。SDK 的流式迭代没有正文，程序却将其作为成功结果保存。这直接复现了当前零字输出的机制。
2. 此前只有 85～94 个字符开场白的三次请求，均由本地 12 秒正文静默超时主动关闭；不是日志确认的模型正常结束。程序又将这种超时当作成功。
3. 另外几次请求存在明确的上游不可用、首批正文超时、HTTP/2 流中断。这些属于当时的 API 网关/上游链路故障，现有证据无法进一步区分网关和底层模型服务。

章节解析正常，后处理没有删除正文。上下文材料不足属于另一项质量问题，不解释 HTML 响应或空流。
